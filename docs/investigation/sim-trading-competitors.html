01结论

  1. 先分类，再比较。璇玑与牛牛是同类竞品（本地 A 股工作台），可以直接比功能与体验；openctp、IG、TradingView 是另外两类，不能按「功能多少」排序，只能按「能借什么」评估。
  2. 视觉与图表：TradingView 最强，IG 次之。两款本地产品是仪表盘水平；openctp 没有自己的用户界面，只有 API 与第三方客户端。
  3. 模拟盘内核：璇玑最严谨，openctp 最真实，IG 与 TradingView 最成熟。璇玑赢在确定性账本与对账；openctp 背后是真实撮合引擎，但规则封闭；IG 与 TradingView 的模拟账户可直接商用，但不可定制。
  4. 集成与合作：只有后三款有对外接入模式。openctp 是 CTPAPI 兼容 + ToB HTTP 接口，IG 是 REST / Lightstreamer / FIX / B2B OAuth，TradingView 是券商 REST 规范 + 图表库授权。两款本地产品没有对外接口。
  5. 没有一款同时具备「专业图表 + 确定性账本 + 可接入契约」。这正是我们的空位：图表借 TradingView 的产品标准，账本借璇玑的纪律，契约借 openctp 的兼容思路，交易前预览借 IG。
  6. 落地路线：薄插件 + 复用数据层 + 只做模拟内核与复盘。不新建独立 Web 壳，不引入 Python，不重写行情采集。璇玑没有 License，任何代码都不能复制。
一句话：做「模拟盘 + 图表 + 复盘」三件事，把这几款产品里最成熟的三套做法拼起来，而不是复刻任意一款产品。

03五款产品速写

Online platform · 图表与券商接入

TradingView

全球最大的图表 SaaS。Paper Trading 是它内置的一个「模拟券商」：默认 10 万 USD，保证金率按资产类别配置（股票 100%、期货 5%、外汇 2%），佣金可开可关。下单接口只返回 pending，成交与持仓由推送或轮询回填。

  • 可借鉴：专业图表交互、下单 ticket、交易前体验、券商接入的产品化方式（137 家券商列表 + The Leap 比赛）。
  • 不可依赖：闭源；Paper Trading 没有公开 API，只能在网页里用；完整券商规范要签协议。

Online platform · 受监管券商

IG demo

老牌 CFD 券商的模拟环境。demo 与 live 同构：独立域名（demo-deal / demo-charts / demo-wtp / demo-api），同一套前端代码，靠主机名切换。Web 平台是单页微前端，业务接口收敛成同源 9 个 BFF 前缀，认证用 CST / X-SECURITY-TOKEN 请求头，不用 Cookie。

  • 可借鉴：下单前双预览（保证金 + 费用）、Lightstreamer 流式行情、环境同构部署、事务边界清楚的 BFF。
  • 不可依赖：闭源；独立 demo 不能申请 API key；撮合与账本规则不公开。

Open infrastructure · CTP 生态

openctp

用 CTPAPI 兼容接口把多家柜台统一起来，同时提供托管模拟环境（7x24 / 仿真 / vip），背后是自研闭源 TTS 柜台。撮合分两种：做市模式（按实盘盘口）与用户间撮合（仅 TEST / BTC / MINUS 三个合约）。另有免费数据中心与 ToB HTTP 接口。

  • 可借鉴：接口契约优先、做市 + 用户间撮合双模式、三套环境分层、ToB 开户/出入金/强平的产品化。
  • 不可依赖：TTS 闭源；撮合规则固定；必须联网与注册账号。

Local workbench · 确定性优先

璇玑

面向 A 股的本机量化研究与模拟执行工作台。核心是「确定性」：独立 F5 账本、十项对账、跨批次幂等与重放、风控失败关闭、研究与执行权限分离。另有 58 个登记因子、Qlib 实验与影子 AI 研究。

  • 可借鉴：账本纪律（确定性、对账、审计、失败关闭），以及「研究产物不能直接下单」的权限边界。
  • 不可依赖：无 License（代码不可复制）；Windows 单机；Node + Python 双运行时；图表很弱。

Local workbench · 产品化优先

牛牛1号

以 A 股模拟交易为核心的市场研究工作台。Vue 3 + FastAPI，4 套主题、9 个页面、管理台、飞书/钉钉/企微/TG 通知、NewsNow 快讯、OpenAI 兼容模型决策。Docker 一键部署，Apache-2.0。

  • 可借鉴：信息架构与复盘体验（账户总览、收益曲线、交易日历、操作日志）、主题系统、通知集成、部署方式。
  • 不可依赖：14,456 行单文件的交易核心、196 KB + 124 KB 的 CSS、双运行时。

Architecture技术选择

  • 单运行时。Node/TS，不引入 Python。数据用 FTShare，历史 K 线用 dsh_kline。
  • 薄界面。宿主 UI primitives + 工具卡片，不写独立路由与外壳；主题跟随宿主。
  • 引擎与界面分离。账户、订单、成交、费用、风控、账本做成纯函数模块；界面只读投影。
  • 确定性。同一输入得到同一账本；规则带版本号，便于重放与测试。
  • 先定审计事件。decision / order / fill / position / fee / risk 六类事件，再写引擎。
  • 测试进 CI。引擎单测 + 账本快照回归，每次提交跑。

Pitfalls避坑清单

范围

别做研究平台

因子、Qlib、新闻聚合、大模型自动交易会把插件拖成十几万行。这些是竞品的主业。

架构

别做独立 Web 壳

宿主已有侧栏、卡片、设置、主题。另起一个 Web 应用，等于放弃集成优势。

数据

别重写行情采集

两款本地竞品都自带东财/腾讯抓取。本仓 FTShare 与 dsh_kline 已覆盖。

代码

别让单文件膨胀

牛牛 practice_trader.py 1.44 万行是反面教材。引擎按域拆文件。

样式

别堆颜色和 CSS

牛牛 521 色 / 320 KB CSS；璇玑样式散在 TSX。用宿主 token，图表配色 ≤6 个。

许可

别无许可抄代码

璇玑没有 License，默认保留所有权利。可学设计，不能复制代码。

质量

别跳过 CI

璇玑 150 个测试却不接 CI。账本回归必须每次提交跑。

产品

别拿 AI 当卖点先做

璇玑已把 AI 控制面退役，牛牛把模型限定为可选。先做对账本与图表。
