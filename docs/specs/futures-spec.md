## 1 背景与判断

现状插件只做 A 股现货：现金多头、T+1、固定比例涨跌停、印花税、09:15–15:00 时段（`src/core/risk.ts`、`src/core/price-limit.ts`、`src/core/fees.ts`、`src/core/session.ts`）。

期货不是「加个代码前缀」，三处是架构级冲突：

| 冲突 | 现状 | 期货 |
| --- | --- | --- |
| 交易日归属 | 日历日 15:00 收盘 / 次日 09:15 开盘 | 21:00 起的夜盘属于**次一交易日**（实测：21:03 的 bar `trade_date` 已是下一交易日） |
| 资金 | 全额现金，货银两讫 | 保证金占用，逐日盯市，可爆仓 |
| 价格精度 | 统一两位小数 | 按合约 `tickSize` 量化（0.005 / 0.2 / 1 / 2 元都有） |

结论：**独立账户、独立账本、独立风控**，共存于同一插件包，共享面板壳与行情入口。不往股票账本里加双边/保证金字段（会把已稳定的重放与对账打散）。

## 2 目标与非目标

**目标**

- 人：选合约 → 开/平仓（多空 × 市价限价）→ 看保证金、风险度、盯市盈亏 → 复盘。
- 模型：用工具做同样的事，与面板写同一本账。
- 账本确定、可审计、可重放；重启不丢；异常失败关闭。
- 行情/合约/结算数据缺失时降级，面板与账本仍可用。

**非目标（本期不做）**

- 交割、仓单、套保额度、组合保证金（单向大边优惠）、期权、标准仓单质押。
- 银行间债券远期（实测 `NIB` 交易所 32 个合约，无行情接口，直接排除）。
- L2 盘口、逐笔、成交量约束撮合（FTShare 无深度数据）。
- 时间加速、夜盘以外的交易时段自定义。

## 4 数据契约（实测事实）

### 4.1 可用接口

| 用途 | 接口 | 关键返回 / 限制 |
| --- | --- | --- |
| 合约主索引 | `ft_v1_futures_futures_base_data` | 全量 4 页（500/页）共 **905 个唯一合约**；含 `multiplier`、`min_put_price_info`（tick 文本）、`margin_info`、`trade_hours_info`、`de_list_tdate`、`symbol_cn_name`；每合约返回 2 行（`future_type` null/2），须去重 |
| 实时报价 | `ft_v4_futures_realtime_day_kline` | 当日 OHLC + `volume`/`amount`/`open_interest`/`vwap`；**无昨结、无涨跌停**；单次 ≤20 合约 |
| 盘中最新价 | `ft_v4_futures_minutes_realtime` | 当日全部分钟（**从上一晚 21:00 起**），含 `pre_settlement_price`、`high_limit_price`、`low_limit_price`、`open_interest`、`updated_at` |
| 历史日 K | `ft_v1_futures_kline` | 收盘后含当日行；`settlement_price` 不提供（恒 0） |
| 历史分钟 | `ft_v2_futures_minutes` | 跨度 ≤72h；当日数据 16:30 后可查 |
| 涨跌停 | `ft_v1_futures_ft_limit` | 必填 `exchange`；`up_limit`/`down_limit`/`m_ratio`（当日保证金比例） |
| 结算参数 | `ft_v1_futures_fut_settle` | `settle`、`long_margin_rate`、`trading_fee`（元/手）、`trading_fee_rate`、`offset_today_fee`（平今）；**CFFEX 整所无数据** |
| 交易日历 | `ft_v1_time_trading_calendar` | `market` 只接受 `cn`/`hk`；期货与 A 股节假日一致，用 `cn` 即可 |

### 4.2 三个必须处理的坑

1. **后缀三套并存**，内部统一用 CTP 格式（行情接口认的那个），其余入口转换：

| 入口 | 后缀 | 例 |
| --- | --- | --- |
| 行情（日K/分钟/实时） | `.SHFE .INE .DCE .CZCE .CFFEX .GFEX` | `RB2611.SHFE`、`IF2611.CFFEX` |
| 合约基础数据 | `.SHF .INE .DCE .CZC .CFE .GFE` | `TA611.CZC`、`IF2611.CFE` |
| 涨跌停 / 结算参数 | `.SHF .INE .DCE .ZCE .CFX .GFE` | `RB2611.SHF`、`IF2611.CFX` |

   郑商所是**三位月份**（`TA611.CZCE`、`CF611.CZCE`），不是 `TA2611`。传错后缀不报错、返回 0 行，必须靠归一映射而不是试错。

2. **`ft_v1_search` 搜不到期货**（`螺纹钢`、`IF2611` 均 0 行），期货搜索必须自建索引。`ft_v1_futures_futures_lists` 不适合当索引：当日数据 20:20 后才开放，且实测 600 条里**缺 SHFE**。索引源用 4.1 的合约主索引。

3. **涨跌停取整差 1 tick**：`ft_limit` 给 `RB2611` 3273（四舍五入，交易所口径），实时分钟给 3272（向下取整）。以 `ft_limit` 为准，缺该所数据时退回分钟字段并容忍 1 tick。

### 4.3 行情语义

- 报价新鲜度看分钟接口 `updated_at`；日 K 的 `datetime` 恒为 15:00，不能当行情时间。
- 21:00 后所有实时接口的 `trade_date` 已归属**次一交易日**，成交归属直接用它，不用自算。
- 盘中（09:00–15:00、21:00–次日 02:30）分钟接口返回当日累计；非交易时段返回最近交易日全量（**盘前 09:00 前的行为待盘中验证**，见 §10）。

## 5 交易规则

| 规则 | 定义 |
| --- | --- |
| 可交易合约 〔待确认 D9〕 | 有合约要素且在最新交易日有成交量（`volume > 0`）；排除 `NIB`、排除无 `multiplier` 的合约 |
| 下单单位 | 手（`qty` 为正整数），成交额 = 价格 × `multiplier` × 手数 |
| 方向 | 开多 / 开空 / 平多 / 平空四类；多空持仓分开存，不互相冲销 |
| 平今 〔待确认 D5〕 | 上期所区分平今与平昨（`offset_today_fee` 常为平昨的 2 倍，实测 AP 5→10）；其他所不区分，按「平今优先」处理 |
| T+0 | 当日可平当日开仓；无 T+1 锁定 |
| 成交价 | 延续现有 M2：一次全成，成交价 = 判定所用报价的最新价，按合约 tick 量化，无滑点；不做部分成交 |
| 涨跌停 | 成交价与限价都必须落在 `[low_limit, up_limit]`；以 `ft_limit` 为准 |
| 保证金 〔待确认 D6/D7〕 | 每手 = 价格 × `multiplier` × 比例；比例取 `ft_limit.m_ratio`（当日），缺失退回 `fut_settle.long_margin_rate`，再退回 `base_data.margin_info` 文本；多空分开收取，`settings.marginUplift` 默认 0 |
| 手续费 〔待确认 D8〕 | 优先 `trading_fee`（元/手）× 手数；平今用 `offset_today_fee`；两者皆 0 时用 `trading_fee_rate` × 成交额（**单位待核**，见 §10）。缺失时按 `settings.defaultFeePerLotCents` 计，暂不加期货公司加收 |
| 盯市 〔待确认 D16〕 | 收盘后按当日收盘价重算持仓市值；有 `settle` 的合约可改用结算价（CFFEX 无数据，统一收盘价才能跨所可比） |
| 权益 | 权益 = 可用现金 + 保证金占用 + 浮动盈亏（盯市后浮动盈亏已实现化） |
| 风险度 〔待确认 D3〕 | 保证金占用 / 权益；≥ 80% 警告，≥ 100% 强平 |
| 强平 〔待确认 D15〕 | 收盘后检查，超线则按收盘价全部平仓，写 `futures.forced_liquidation` 事件并在面板提示 |
| 到期 〔待确认 D4/D14〕 | 距 `de_list_tdate` ≤ 3 个交易日禁止开仓；到期日收盘强平剩余持仓（不自动移仓） |
| 挂单 | 当日有效；夜盘下的单归属次一交易日（用接口 `trade_date`）；收盘未成交撤单 |
| 时段 〔待确认 D1/D12〕 | 由 `base_data.trade_hours_info` 解析 + 内置品种兜底表；解析失败按品种默认（日盘 09:00–11:30、13:30–15:00，是否有夜盘见兜底表）。中金所 09:30–11:30、13:00–15:00（国债 15:15），无夜盘 |
| 交易日 | 结算完成（15:30）即推进到下一交易日（pre_open）；有夜盘品种 21:00 起可交易，无夜盘品种次日 09:00 起 |

## 7 账本与状态

- 路径：`$DSH_HOME/paper-trading/futures/events.jsonl`，备份目录同构；现金只能由「初始资金 + 重置」改变（不做出入金，见 D13）。
- 账本版本 `futures-v1`，与股票 `PAPER_LEDGER_VERSION=3` 各自演进，不共享事件 schema。
- 事件类型：`account.opened`、`account.reset`、`order.submitted`、`order.filled`、`order.rejected`、`order.canceled`、`position.forced_liquidation`、`day.opened`、`day.closed`、`ledger.violation`、`ledger.repaired`。
- 不变量（每次重放校验）：`现金 + Σ保证金 = 权益 − Σ浮盈`、手数与成交事故意一致、保证金系数非负。
- 失败关闭：任一对账不变量被破坏则置 `blocked`，拒绝新单，保留导出与重置入口（与股票账户一致）。

## 8 接口与工具

- RPC 端点：`futures/account`、`futures/contracts`、`futures/quote`、`futures/preview`、`futures/order`、`futures/cancel`、`futures/positions`、`futures/orders`、`futures/review`、`futures/tick`。沿用现路由 `/api/ft-paper-trading` 与四态数据契约。
- 工具参数（与股票版差异）：`qty` 单位手；`side` 取 `long`/`short`；新增 `offset` 取 `open`/`close`；预览返回 `marginCents`、`feesCents`、`riskRatio`、`maxOpenQty`。〔待确认 D10：工具是否独立〕
- 工具输出保留「一句话摘要 + 结构化数据」的既有形状，模型不必读原始 JSON。

- 顶部账户切换：`股票 | 期货`，切换后统计卡文案改为「总权益 / 可用资金 / 浮动盈亏 / 风险度」〔待确认 D11：首期是否含行情页签〕。

- 提示语：临近交割、保证金不足、风险度超线、非交易时段，一句话说清，不写大段说明。

## 11 验收标准

| # | 用例 | 期望 |
| --- | --- | --- |
| A1 | 21:30 开多 `rb2611` 1 手 | 成交记入次一交易日；复盘该日有这笔成交 |
| A2 | 次日 15:00 结算 | 日快照权益 = 现金 + 保证金 + 按当日收盘价重算的浮动盈亏 |
| A3 | 开 1 手 `IF2611`（100 万初始资金） | 保证金 ≈ 14.4 万（3999.6×300×12%），风险度 ≈ 14% |
| A4 | 限价买单低于最新价 | 挂单，不成交，撤单后现金不变 |
| A5 | 限价买单高于最新价 | 以最新价成交（取 `min(限价, 最新价)`） |
| A6 | 平今 vs 平昨 | 上期所品种按 `offset_today_fee` / `trading_fee` 分别计费，预览与成交一致 |
| A7 | 保证金不足 | 拒单，提示差额，账户不变 |
| A8 | 价格超出涨跌停 | 拒单，提示区间 |
| A9 | 距到期 2 个交易日开仓 | 拒绝，提示临近交割 |
| A10 | 收盘风险度 105% | 收盘强平，持仓清零，事件与提示留痕 |
| A11 | 杀进程重启 | 现金、持仓、订单、权益曲线与重启前一致 |
| A12 | 期货接口全部 denied | 面板可用、账本可读、可手填参考价平仓，文案说明无权限 |
| A13 | 股票账本与期货账本并存 | 两本账互不读取、互不影响，各自可重置 |
| A14 | 事件重放 | 同一账本重放结果与实时状态逐字段一致；对账不变量始终成立 |

## 13 待确认的产品决策

> 正文里凡是标了 `〔待确认 Dx〕` 的地方，都是本文**替你先定了默认值**的参数，不是你已点头的结论。
> 下表「建议默认」是正文当时取值；**MVP 拍板以 [futures-mvp.md](futures-mvp.md) §1 为准**（D1 夜盘不做、D11 四页签、D12 仅商品等）。

| # | 决策点 | 建议默认 | 换了会怎样 |
| --- | --- | --- | --- |
| D1 | 首期是否支持夜盘交易 | 支持（21:00–次日 02:30 按品种） | 不做：日切逻辑能砍一半（不用跨自然日归交易日），但模拟盘完全看不到隔夜跳空，期货最核心的风险体验缺失 |
| D2 | 期货账户初始资金 | 100 万元 | 太低开不了 IF（一手保证金约 14.4 万）；太高失去资金约束的意义。也可做「可配置初始资金」 |
| D3 | 强平线与警告线 | 风险度 100% 强平、80% 警告 | 收紧到 90% 会频繁爆仓；放宽到 120% 等于默许穿仓（需额外处理负权益） |
| D4 | 到期前禁开仓天数 | 3 个交易日 | 按交易所自然人规则更严格（商品期货需在交割月前平仓），实现更琐碎；取 0 则会在最后交易日出现无法平仓的持仓 |
| D5 | 平今处理粒度 | 上期所区分平今/平昨，其他所平今优先 | 全部平今优先：手续费误差小、实现简单，但上期所品种费用不准；全部区分：平昨不足时要拆单，交互变复杂 |
| D6 | 多空双向保证金 | 分开收取（多空各占一份） | 单向大边（交易所对同品种双向持仓只收大边）需按品种聚合，账单更真实但风控实现复杂度上升一档 |
| D7 | 保证金上浮 | 交易所比例 +0 | 期货公司普遍上浮 2–5pp；上浮后更接近实盘但需要「期货公司参数」这一层概念 |
| D8 | 手续费加收倍数 | 1.0（只收交易所标准） | 设 2.0 更接近期货公司实收；不影响撮合正确性，只影响复盘成本 |
| D9 | 可交易合约范围 | 当日有成交量（`volume > 0`）即可 | 只放主力合约：简单但要维护主力判定（上游没有该字段）；不限成交量：会出现在僵尸远月合约上「无限成交」的假象 |
| D10 | Agent 工具命名 | 新增 8 个 `futures_*`，与 `paper_*` 平行 | 复用 `paper_*` 加 `asset` 参数：工具总数少一半，但两个资产类别的参数语义（股数/手数、买卖/开平）混在同一工具里，模型更易用错 |
| D11 | 首期面板范围 | 交易、行情、持仓、订单、复盘五页签 | 砍到「交易+持仓+复盘」三页：省 1–2 人日，但行情页是期货选合约的主入口，砍掉后只能靠搜索框 |
| D12 | 首期是否纳入国债/股指期货 | 纳入（数据可用），但国债 15:15 收盘单独处理 | 只做商品期货：时段规则简单一档，但中金所无夜盘、无结算参数这两个坑也一并绕开了 |
| D13 | 出入金 | 不做，只有「初始资金 + 重置」 | 加入金/出金要动账本事件与权益基线，属于账本语义变更，建议单独一批 |
| D14 | 到期处理方式 | 强平收场 | 自动移仓到下一个主力合约：需要主力判定 + 换月规则，且用户没授权就换仓是「替你交易」，不建议 |
| D15 | 强平执行时点 | 收盘后检查并强平 | 盘中实时盯风险度：要按分钟轮询所有持仓合约，请求量与误触（一根插针就爆）都上升，建议 P1 再议 |
| D16 | 盯市价 | 统一用当日收盘价 | 有 `settle` 的交易所用结算价（更真实），但 CFFEX 缺数据会变成两套口径，复盘可比性变差 |
| D17 | 备选合约 | 复用现有备选，全局一份（未按账户隔离） | 不做：每次从搜索/行情页进，流程变长 |
